# M-05 数据来源、字段口径与敏感边界

## 在哪里看

进入“数据源与映射”，A800 数据源上方新增“算力数据来源与使用边界”。十类数据逐一登记来源阶段、权威来源标识、负责人、更新要求、最大允许年龄、敏感等级和冲突处理方式。点击“字段”可查看实际表、字段、单位及状态含义；原有本体字段映射继续保留。

管理员和编辑员可修改登记。保存后登记版本加一；旧版本提交被拒绝。修改与操作审计在同一个平台事务中，审计写入失败时修改也回滚。不会只改名称却丢失原登记内容。

上述负责人是需求中的对接责任登记，不创建同名平台账号，也不把样例员工编号当真实员工。SIMULATED、PLATFORM、EXTERNAL_PENDING、CONNECTED 分别标记阶段；把登记改成 CONNECTED 也不能证明采集已连通，仍须采集与质量验证。

## 哪些数据可以给 Agent

`GET /api/compute/data-contract` 返回六项必填（subjectId、resourceId、eventType、timestamp、value、source）、GPU 稳定识别和 UTC 契约，以及过滤后的字段目录。账号/组织和账号原始审计明细不进入通用知识库；资源原始使用日志也不能整批导入。

`ComputeDataAssetService.projectForAgent` 按资产、表和已登记字段的正向清单投影。敏感资产、敏感字段、未知字段、嵌套原始报文、命令参数、挂载、镜像引用等不会直接输出；待接入来源不输出业务值。后续 Agent 工具必须调用这一层，不能把数据库整行直接序列化给模型。

平台预留与监控运行状态分别代表两种事实。冲突时按权威来源核对，资源安全问题先阻断；不能因为监控说空闲就覆盖预留，更不能把旧观测的时间更新成现在。采集间隔、valid_until、最大允许年龄是不同设置。

这里交付登记、字段解释和数据契约，不接通 DCGM、邮件、账号系统或 K8S。实际接收、拒收原因、乱序和来源冲突处理属于 M-09/N-03/N-16；契约明确 `ingestionEnabled=false`。

## 存储、接口与验证

- 平台新增 V9，保存十类资产与字段目录，不改旧映射。每次规则发布固定当时的资产版本、来源、负责人、敏感等级和时效登记；修改目录不会暗中改写旧发布。
- `GET /api/compute/data-assets`、`GET /api/compute/data-assets/{code}` 查询登记；`PUT /api/compute/data-assets/{code}` 需 ADMIN/EDITOR 和最新 version。
- ComputeDataAssetTest 验证十类来源、字段实际存在、敏感过滤、未知字段丢弃、版本冲突、非法时效和审计失败回滚。
- HTTP 回归验证十类目录、六项契约、敏感字段过滤，保留发布和申请接口回归；前端构建检查新页面。
- 本次 15 项隔离数据库及 HTTP 测试通过，前端构建通过。隔离库辅助类改为复用同一数据源，避免测试事务和 JDBC 写入使用不同连接来源；同时补验平台发布回滚后发布行和同步行都不存在。
