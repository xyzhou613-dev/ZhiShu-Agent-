## 与执行器同学对齐什么

- 正式决定固定 `rule_set.id`，从集合成员取实际 `rule_version.id`。不要用页面演练或草稿作为运行依据。
- 八条计算统一调用 ComputeResourceMath；容量查询使用服务端账本，不采信 Agent 自报容量或已通过标签。
- 预留与交接使用 ComputeBusinessTransactions.writeLocked，按节点共享容量、卡组的顺序锁定；锁内重查队首、证据、持有、容量和规则。异常向外抛以回滚。
- 预留是 PENDING，实际持有只认 OCCUPIED。激活前登记准确的组内使用卡；关闭旧持有、激活分配、更新组指针和新增持有必须在同一业务事务里。
- 停服是否确认、GPU 是否释放、回执未知如何核对，由 N-11/N-12 的真实流程回执决定，不能由 Agent 填一个布尔值跳过。
- 使用固定操作编号查询 execution_action。恢复责任绑定原 deployment_revision.id，不跟随最新部署修订变化。
- 给 Agent 的业务数据走 ComputeDataAssetService.projectForAgent；敏感原始日志、命令和挂载配置不能整行传给模型。

本次没有新增另一套调度器或状态机，没有启动真实训练、停止模型或发送通知。完整“申请→预留→启动→结束”路径仍由同学负责的 N 类功能与这些基础接口衔接。共享草稿没有自动发布或激活。

已对齐同学的生效规则执行与运行记录 API；该入口保留 CALLER 事实来源和 authorizesExecution=false，运行记录不冒充批准或节点执行结果。参见 [同学的规则执行接口文档](A800-compute-rule-evaluation-api.md)。
